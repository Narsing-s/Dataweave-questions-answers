# Contributor Roadmap

This roadmap is designed to turn a first-time visitor into a useful contributor without lowering the quality bar.

## Level 1 — First contribution

Easy, low-risk tasks:

- report a wrong output;
- report a duplicate or overlapping question;
- fix a typo or unclear explanation;
- improve an edge-case explanation;
- improve documentation/navigation.

## Level 2 — Technical contribution

- runtime-test an existing example;
- document a DataWeave version-specific behavior;
- improve a search/filter experience;
- improve Explorer or Practice Bank UI;
- add validation or quality tooling.

## Level 3 — Content contribution

- propose a genuinely missing DataWeave concept;
- create an advanced transformation;
- create a critical interview scenario;
- add a production-style API transformation;
- add a debugging or performance scenario.

Every new question must pass the conceptual-uniqueness check. Rewording an existing question or changing only values does not count.

## Level 4 — Maintainer-quality contribution

- improve duplicate-detection logic;
- improve dataset quality checks;
- review community submissions;
- improve release automation;
- improve contributor documentation;
- help verify examples across DataWeave/Mule runtime versions.

## Recommended path

**Start with a Discussion → validate the idea → open/claim an Issue → submit a focused PR → pass validation/review → get merged.**

## What maintainers look for

1. Conceptual uniqueness
2. Technical correctness
3. Clear explanation
4. Reproducible input/output
5. Appropriate difficulty
6. Useful real-world or interview context
7. Clean, focused changes

Quality is more important than increasing the question count.
